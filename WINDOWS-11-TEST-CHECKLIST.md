# RC19: Windows 11 test checklist

UNSIGNED TEST PREVIEW. Non-production only. Mac-assembled using unchanged Windows Node runtime bytes from RC17. This application revision still needs Windows 11 acceptance. Not a native installer or Store release. Do not disable security or organizational controls to run it.

1. Close the previous FUSE app window and console after saving. Extract the complete RC19 ZIP into a new folder, not over a running copy. Start **Start FUSE.cmd**. Expect the branded Edge/Chrome app window, no normal tab strip and no admin prompt. If blocked by policy, report **Blocked**, not Pass.
2. Existing RC18 queries/connections should remain under the same Windows account. Confirm password protection still works after restarting; passwords must not become plaintext. Do not delete the user's FUSE app-data folder when replacing the ZIP.
3. New connection: default report folder is `/Custom/FUSE`, editable. Use authorized non-production credentials and the correct HCM/FSCM preset. **Save & prepare** checks/creates the chosen folder and missing preset pair, then runs a one-row probe. Visible object names must not contain doubled `.xdm`/`.xdo`. Service paths retain the extensions. For old connections, edit and choose **Use /Custom/FUSE**; old catalog content is not removed automatically. Ask the tenant administrator before cleaning old objects.
4. Retry the original `SELECT *` with 100 rows. Record success, displayed count, any batch note or the exact redacted error. Also test fewer rows, explicit columns, cancellation and a bounded 1,000-row request. Byte/cell/query timeout limits still apply. A low row limit does not make a wide or expensive query cheap.
5. Editor: with `FROM PER_ALL_PEOPLE_F PAPF`, type `PAPF.` and expect only that table's columns. Select `PERSON_ID`: keep `PAPF.PERSON_ID`. Separately type bare `PER` and select `PERSON_ID`: insert just `PERSON_ID`, without an unsolicited table/alias prefix.
6. **Save** a query. Confirm a real `.sql` file in Documents/FUSE/Queries with exact SQL text. Select a custom absolute folder in **Settings → SQL files** and repeat. Edit a previously saved file externally, then try saving again: FUSE must refuse the overwrite and retain your library/draft copy. File renames/moves/deletes in the library do not delete earlier disk files.
7. **Import files** and **Import folder** with nested UTF-8 SQL files. Confirm originals are unchanged, nested folders retained and duplicate names disambiguated. Pin a file and a folder; the pinned filter must include the folder's descendants. Restart and check saved items/pins remain.
8. Schema: table list stays alphabetical while selecting/favoriting. Inspect PAPF/absence columns, comments and keys. Open an official documentation link. Missing source metadata must be shown as unknown, not guessed.
9. MCP optional: copy fresh RC19 setup into a separate client project, preserving unrelated settings. Expect five metadata tools plus four request/status tools. With FUSE closed, metadata lookups still work and mutation requests fail clearly. Open FUSE: both action permissions start off. Enable creation, request a synthetic query/folder, approve it in FUSE and verify the file. Enable execution only for authorized non-production tests; review the exact SQL/connection for each request. Results stay in FUSE; the agent gets only status/counts, never rows or raw service errors. Turning permissions off revokes queued requests; restart resets both to off. Do not separately grant the agent access to FUSE's data/export folders.
10. Review **Settings → About & legal notices**. Confirm there is no claim of Oracle affiliation, production readiness, signed FUSE distribution or enterprise-policy bypass.

Reply with Windows build, browser version, package SHA-256 and **Pass / Fail / Blocked / Not tested** for each item. Share only redacted error text/screenshots. Exclude passwords, tenant URLs, usernames, real sensitive SQL literals and result rows.
